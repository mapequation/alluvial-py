Plotting#

alluvial.plot(networks, ax=None, **kwargs)#

Lay out and draw in one call: draw(layout(networks, **layout_kwargs), ax, **draw_kwargs).

Parameters:

  • networks (sequence of str or PathLike, infomap.Infomap, Infomap JSON dict or NetworkFile) – Networks from left to right (see alluvial.layout).

  • ax (matplotlib.axes.Axes, optional) – Target axes; by default a new figure at one layout px per point.

  • **kwargs – Keyword arguments of alluvial.layout (including LayoutOptions fields) and alluvial.draw.

Returns:

get_artists(ax) returns the created artists.

Return type:

matplotlib.axes.Axes

Examples

>>> ax = alluvial.plot([im_2020, im_2021], names=["2020", "2021"])
>>> fig, ax = plt.subplots(figsize=(3.4, 2.4), layout="constrained")
>>> alluvial.plot(["t0.ftree", "t1.ftree"], ax=ax, colors="module_id", palette="tab10")
alluvial.draw(geometry, ax=None, *, palette=None, default_color=None, module_labels=True, network_labels=True, fontsize=None, network_fontsize=None, max_label_lines=None, max_label_width='auto', avoid_label_overlap=True, label_pad=3.0, streamline_alpha=0.8, gradient=True, edgecolor='face', linewidth=0.3, rasterized=False, hierarchy=True, legend=False, label_colors='auto', module_kw=None, streamline_kw=None, hierarchy_kw=None, text_kw=None, label_kw=None, network_label_kw=None)#

Draw a laid-out alluvial diagram on a matplotlib Axes.

The shapes are in layout px (data coordinates, y up); every text size, gap and margin is in points. At each draw the labels and the axes limits are fitted to the axes size, so the diagram fills the axes, every text stays inside it and font sizes are exact at any figure size (also under layout="constrained" and after resizing).

Parameters:

  • geometry (AlluvialGeometry) – Result of alluvial.layout.

  • ax (matplotlib.axes.Axes, optional) – Target axes. By default a new figure is created at one layout px per point, sized to fit the labels.

  • palette (sequence of colours, str or Colormap, optional) – Highlight colours, or a matplotlib colormap (name). Qualitative maps are used as is, continuous maps are sampled to the needed number of colours. Defaults to geometry.palette. Indices beyond the palette cycle it, with a warning.

  • default_color (colour, optional) – Colour of unhighlighted modules; defaults to the web app’s #b6b69f.

  • module_labels (bool, default True) – Draw module name labels (first and last network) and network names (below each network).

  • network_labels (bool, default True) – Draw module name labels (first and last network) and network names (below each network).

  • fontsize (float or str, optional) – Module label size in points or a relative size; defaults to "small" (rcParams["font.size"] / 1.2).

  • network_fontsize (float or str, optional) – Network name size; defaults to "medium" (rcParams["font.size"]).

  • max_label_lines (int, optional) – Cap on the names (lines) per module label. By default as many as fit (the web app rule: one line per 1.8 em of module height, an odd number).

  • max_label_width (float, "auto" or None, default "auto") – Longer label lines are truncated with an ellipsis to this width in points. "auto" keeps each label column within a quarter of the axes width (no cap on a figure draw made itself); None never truncates.

  • avoid_label_overlap (bool, default True) – Where labels of neighbouring modules would overlap, drop lines of the smaller module, then its whole label. False reproduces the web app, which lets them overlap.

  • label_pad (float, default 3) – Gap between a module and its label, in points.

  • streamline_alpha (float, default 0.8) – Streamline opacity.

  • gradient (bool, default True) – Fill streamlines whose ends differ in colour with a horizontal gradient (as the web app does; a small embedded image, clipped to the streamline). If False they use the colour of their left end, all vector.

  • edgecolor (default "face", 0.3) – Module edge style. The default hairline in the face colour hides the antialiasing seams between stacked groups and at streamline ends; use linewidth=0 for exact web app rectangles.

  • linewidth (default "face", 0.3) – Module edge style. The default hairline in the face colour hides the antialiasing seams between stacked groups and at streamline ends; use linewidth=0 for exact web app rectangles.

  • rasterized (bool, default False) – Rasterize modules and streamlines (texts stay vector) in PDF/SVG output, for very large diagrams.

  • hierarchy (bool or {"shadow", "outline"}, default True) – How to show the parent modules of expanded sub-modules (NetworkGeometry.outlines, from layout(module_level=...) or expand=), as the web app does: "shadow" (or True) draws a gray box behind each parent, offset right and down by 5 px per level; "outline" a dotted rounded box around it. False or None draws nothing. A diagram of top modules has no outlines either way.

  • legend (bool, default False) – Add a legend of the highlight labels (layout(highlight=...)) above the diagram; see alluvial.legend.

  • label_colors (bool or "auto", default "auto") – Colour each module label line by its node’s highlight colour, as the web app does (black when gray). "auto" does so only for a diagram with highlight labels (layout(highlight=...)), where the colour tells which names belong to a group.

  • module_kw (dict, optional) – Extra Rectangle / streamline properties (e.g. {"hatch": "//", "edgecolor": "white"}, {"alpha": 0.6}). A hatch is drawn in the edge colour, which is the face colour by default.

  • streamline_kw (dict, optional) – Extra Rectangle / streamline properties (e.g. {"hatch": "//", "edgecolor": "white"}, {"alpha": 0.6}). A hatch is drawn in the edge colour, which is the face colour by default.

  • hierarchy_kw (dict, optional) – Extra properties of the hierarchy shadows or outlines (e.g. {"facecolor": "0.85"}, {"edgecolor": "k", "alpha": 1}).

  • text_kw (dict, optional) – Extra Text properties for all labels (e.g. {"family": "serif"}).

  • label_kw (dict, optional) – Extra Text properties for module labels or network names only (override text_kw).

  • network_label_kw (dict, optional) – Extra Text properties for module labels or network names only (override text_kw).

Returns:

The axes drawn on, with the axis turned off. get_artists(ax) returns the created artists.

Return type:

matplotlib.axes.Axes

Examples

>>> geom = alluvial.layout(["t0.ftree", "t1.ftree"], names=["2020", "2021"])
>>> fig, ax = plt.subplots(figsize=(3.4, 2.4), layout="constrained")
>>> alluvial.draw(geom, ax, fontsize=6, max_label_lines=3)
>>> fig.savefig("alluvial.pdf")
alluvial.legend(ax, *, other=None, **kwargs)#

Add a legend of the highlight labels (layout(highlight=...)) of the diagram drawn on ax.

By default the legend is a row of colour swatches centred above the diagram, inside the axes. It takes more rows when it is wider than the axes, and the fit makes room for it at every draw. Passing loc or bbox_to_anchor places it like any matplotlib legend instead (no room is made). Calling it again replaces the legend.

Parameters:

  • ax (matplotlib.axes.Axes) – An axes draw or plot drew on.

  • other (str, optional) – Also add an entry in the default (gray) colour with this label, e.g. "other".

  • **kwargs – Axes.legend keywords (e.g. title, fontsize, ncols, frameon).

Returns:

None (with a warning) if the geometry has no highlight labels and no other.

Return type:

matplotlib.legend.Legend or None

Layout and geometry#

alluvial.layout(networks, *, names=None, ids=None, identifier='id', split_layers=False, colors='similarity', module_level=1, expand=None, highlight=None, highlight_colors=None, scheme=None, tone=None, offset=None, restore_state=True, module_order=None, module_names=None, show_bipartite_nodes=None, **options)#

Lay out an alluvial diagram of one or more partitioned networks.

Parameters:

  • networks (iterable of str or PathLike, infomap.Infomap, Infomap JSON dict or NetworkFile) – Networks from left to right. Paths are read by suffix (.tree, .ftree, .stree, .clu, .json); an infomap.Infomap must already have run. A .zip of network files (the web app’s zip upload, or save_diagram) contributes its files in archive order.

  • names (sequence of str, optional) – Network names, one per network (after splitting layers; numbers are converted with str). Defaults to the file basename, "network {i}" for objects, and "<name> layer <k>"-style names for split layers.

  • ids (sequence of str, optional) – Network ids, one per network (after splitting layers): unique, without "--". By default the file stem, "net{i}" for objects or the NetworkFile id, with colliding ids made unique as out, out_2, … An input that is split gets that suffix before splitting (out_2_layer1, …).

  • identifier ({"id", "name"}, default "id") – How nodes are matched across networks: stateId ?? id, or the node name. Applies to paths, dicts and Infomap objects; a NetworkFile keeps the identifiers it was read with.

  • split_layers (bool or sequence of bool, default False) – Split multilayer networks into one network per layer (alluvial.read(..., split_layers=True)); a sequence gives one flag per input. Split layers match their nodes by physical id.

  • colors ({"similarity", "module_id", "nodes", "layer", "physical_id", "hierarchy"} or None, default "similarity") – Colouring operation applied after the build, as in the web app: matching modules across networks, by module id, every node by its module in the first network, by layer id (multilayer networks), by physical node id (state or multilayer networks), or by the module hierarchy (c3’s hierarchy(): sub-modules get colours close to their parent’s, and the same module path gets the same colour in every network; use it with module_level/expand, and scheme, tone and offset set the top-module colours). None keeps the input colours (gray unless the input carries colours). Not allowed with highlight. The default is None when the input carries colours: Infomap JSON with a top-level colors (as written by save_diagram).

  • module_level (int or sequence of int, default 1) – Show sub-modules down to this level (one value, or one per network): every visible module whose sub-modules go that deep is expanded, as when clicking modules in the web app. 1 shows the top modules. With colors="similarity" a sub-module that is not paired with a module of a neighbouring network can stay gray, as in the web app.

  • expand (iterable of (network, module_id), optional) – Modules to expand first, in order. network is an index or a network id, module_id a path string like "1" or "1:2" (looked up when its turn comes, so [(0, "1"), (0, "1:2")] works).

  • highlight (mapping or callable, optional) – Highlight groups of nodes, each in its own colour (the rest stays gray). Either {label: identifiers} (matched against node identifiers, ints allowed; an identifier may belong to one label only), or a callable (NodeInfo) -> label or None evaluated once per node. Labels are kept in mapping order (or first-appearance order) in AlluvialGeometry.highlight_labels, for draw(..., legend=True).

  • highlight_colors (sequence or mapping, optional) – Colours of the highlight labels (a list aligned with the labels, or {label: colour}): colour strings (any matplotlib colour name, "#rrggbb" or "rgb(r, g, b)") or RGB tuples in [0, 1]. Defaults to the scheme.

  • scheme (str or sequence of colours, optional) – The colour scheme of the colouring operations: a web-app scheme name (alluvial.palette.SCHEMES, e.g. "Paired", "Tableau20", "C3 Oklch"; default "C3 Sinebow") or a list of colours. Also the default highlight_colors.

  • tone (str, optional) – The c3 tone (alluvial.palette.TONES: "vivid", "bright", "strong", "deep", "dark", "soft", "pastel", "muted"), the lightness and chroma of the C3 schemes and of colors="hierarchy" with a C3 or interpolated scheme (alluvial.palette.scheme_is_hue_source). Other schemes ignore it. Default "strong" (or the stored tone of a saved diagram).

  • offset (float, optional) – Where c3 puts the first colour, in degrees around the hue source: its hue on the OKLCH hue circle ("C3 Oklch"), else 360 is the whole scheme. Applies where tone does. Default c3’s (alluvial.palette.default_scheme_offset: 245 for "C3 Oklch", else 0), or the stored offset of a saved diagram when its scheme is used.

  • restore_state (bool, default True) – Restore what a saved diagram (save_diagram or the web app’s “Download diagram”) stores besides the networks, colours and expanded modules: the options, the colour scheme with its tone and offset, the custom module orders and the module names, as the web app opens it. Explicit keywords win: a layout option, scheme, tone or offset given here replaces the stored one (another scheme drops the stored offset), and module_order/module_names replace the stored orders/names. Files from different saves, or not all files of one save, restore their module orders and names but not the options (warned). False loads the files as plain Infomap JSON (with their colours and expanded modules).

  • module_order (mapping, optional) – {network: [module_id, ...]}: put these visible modules of a network (index, id, or a name given with names= as a string when exactly one network has it) at these positions, listed bottom to top. The unlisted visible modules keep their relative order above them; an ... (Ellipsis) in the list stands for them, so ["3", ...] puts module 3 at the bottom, [..., "3"] at the top and ["2", ..., "5"] both. Applied after the colouring as one reorder of the web app’s store (TS setModuleOrder: one layout however many modules move; “move up/down” in the web app gives the same order), so sort_modules_by sets the start. Module ids are those shown after expand/module_level (e.g. "1:2"); hidden modules cannot be placed.

  • module_names (mapping or callable, optional) – Custom module names, shown instead of the node names (as the web app’s module name field): either {(network, module_id): name} (network as for module_order) or a callable (ModuleInfo) -> str or None called for every module (also hidden ones) after all other steps. Names are kept in ModuleGeometry.name (save_diagram stores them); the labels are drawn on the first and last network only, as in the web app.

  • show_bipartite_nodes (bool, optional) – False hides the second node type of bipartite networks (node id >= the network’s bipartiteStartId), as the web app’s “Show bipartite nodes” switch. Default True (or the stored value of a saved diagram).

  • **options – Fields of LayoutOptions.

Returns:

Frozen geometry in TS/SVG coordinates (y down).

Return type:

AlluvialGeometry

Raises:

  • ValueError – For an Infomap object that has not run, an unreadable or unsupported file, no networks, an invalid option value, a module to expand that does not exist or has no sub-modules, colors with highlight, or a module_order/module_names entry with an unknown network or module, a module given twice, or (for module_order) a hidden module.

  • FileNotFoundError – For a path that does not exist.

  • TypeError – For an unknown keyword, a single network not wrapped in a list, or an argument of the wrong type.

Warns:

UserWarning – For state networks matched by state id next to networks matched by node id (identifier="id"), a module_level deeper than a network’s module tree, highlight identifiers that match no node, duplicate node identifiers within a network, highlight labels drawn gray or in a shared colour, and a diagram where no node flow is positive.

Notes

The steps run in the web app’s store, in this order: build, expand, module_level, the colouring (colors or highlight), module_order, then module_names. Each is a sequence of the store’s own operations, so the geometry matches the web app bit for bit.

Parameters:

  • module_size ({"flow", "nodes"}, default "flow") – Module height measure.

  • sort_modules_by ({"flow", "nodes", "node_id", "highlight_index"}, default "flow") – Module order key (descending). "node_id" is the mean node id (TS "nodeId").

Raises:

  • TypeError – If a value has the wrong type.

  • ValueError – If a value is out of range or not one of the allowed choices.

Reading and saving#

alluvial.read(source: str | PathLike[str] | Any, *, name: str | None = None, identifier: Literal['id', 'name'] = 'id', states: bool | None = None, network_id: str | None = None, split_layers: Literal[False] = False) → NetworkFile#
alluvial.read(source: str | PathLike[str] | Any, *, name: str | None = None, identifier: Literal['id', 'name'] = 'id', states: bool | None = None, network_id: str | None = None, split_layers: Literal[True]) → list[NetworkFile]

Read one network into a NetworkFile (or, with split_layers=True, one per layer).

Parameters:

  • source (str, PathLike, dict, infomap.Infomap or NetworkFile) – A .tree/.ftree/.stree/.clu path (format from the suffix; Infomap’s -o states files *_states.tree/.ftree/.clu included), an Infomap -o json file (.json) or its parsed dict, an infomap.Infomap that has run, an infomap Result (from im.run(), infomap.run(...) or Network.run(); infomap >= 2.14), or a NetworkFile (returned unchanged unless split). A .zip of network files (the web app’s zip upload, or save_diagram), a directory of network files, or a list of paths gives a list, one NetworkFile per file, in archive (file-name, list) order, or in saved order when they are the files of one saved diagram.

  • name (str, optional) – Network name. Defaults to the file basename, or "network" for objects. For JSON a top-level name comes before these defaults.

  • identifier ({"id", "name"}, default "id") – Node identity across networks, as in the web app: "id" uses state_id if present else the node id, "name" the node name. See State networks below. Ignored with split_layers=True.

  • states (bool, optional) – Infomap objects only: read state nodes. None picks them for state/memory and multilayer networks (like write_tree(states=True)); False reads the physical level (write_tree(states=False)).

  • network_id (str, optional) – Network id. Defaults to the file stem for paths, or name (else "network") for objects. For JSON a top-level string id comes before these defaults.

  • split_layers (bool, default False) – Split a multilayer state network into one network per layer, like the web app’s “split layers” (alluvial.io.split_layers). Layers are ordered by layer id, named "Layer <k>" (or from a JSON layers list), get the ids "<network_id>_layer<k>" and match their nodes by physical id.

Returns:

A list (one per layer) if split_layers is true. Pass it on unpacked: layout([*read(path, split_layers=True)]).

Return type:

NetworkFile or list of NetworkFile

Raises:

  • ValueError – For an unsupported file (Infomap input .net, .csv, Newick, JSON that is not Infomap output, a saved diagram in the 2019 web-app format), a malformed file, a node whose flow is not a finite number, an Infomap object that has not been run, or split_layers=True on a network that is not a multilayer state network.

  • TypeError – For other sources, or an infomap older than 2.14.

Warns:

UserWarning – If several nodes share an identifier (the engine then matches the last one, as in TS; checked per layer after a split), if a tree file has node names with a double quote (Infomap writes them unescaped, so the id column is misread), or if identifier="name" is combined with split_layers=True.

Notes

State networks. Networks are matched node by node through identifier, exactly as in the web app.

  • identifier="id" matches state nodes by state id. That is right for memory networks whose state ids mean the same thing in every network (you assign them in the *States section or with add_state_node). For multilayer networks Infomap assigns the state ids itself, in input order, so the same (layer, node) can get different state ids in two runs: do not match multilayer networks by "id" unless they were built from identically ordered input.

  • identifier="name" matches by physical node name: Infomap writes the physical name (or the physical id when unnamed) for every state node. A physical node with several state nodes then gives duplicate identifiers (warned; matching uses the last one).

  • The physical level (states=False or a write_tree(states=False) file) has one row per physical node and module; a node whose state nodes sit in several modules still appears more than once.

  • split_layers=True shows how one multilayer partition changes across its layers: each layer is a network, and its nodes are matched by physical node id (the identifier mode does not apply, as in the web app). A non-split network next to the layers matches them only if its identifiers are physical ids too, e.g. a first-order .tree read with identifier="id".

alluvial.split_layers(nf, *, id_format='{id}_layer{layer}')#

Split a multilayer state network into one network per layer, like the web app’s “split layers”.

Nodes are matched across the layers by physical node id (the TS "multilayer-expanded" identifiers), whatever identifiers nf was read with. Streamlines then connect the same physical node in adjacent layers.

Parameters:

  • nf (NetworkFile) – A multilayer network read at the state level (its first node has a layer_id). Not mutated: the layers get copies of the nodes.

  • id_format (str, default "{id}_layer{layer}") – Network id of each layer, formatted with id (nf.id) and layer (the layer id as JS String(layerId), e.g. "3"). The result must not contain "--".

Returns:

In JS object key order of the layer ids: non-negative integer ids ascending, then any other ids in first-seen order (only hand-made input has those). Each layer copies every field of nf (header, modules …) and sets id, name (nf.layers entry with a strictly equal id, else "Layer <id>"), nodes (file order), layer_id, original_id = nf.id, the statistics of its nodes and is_expanded = True.

Return type:

list of NetworkFile

Raises:

ValueError – If nf is not multilayer.

Notes

Nodes without a layer_id form a last "Layer undefined" network, as in TS. A JSON layerId: null reads as missing (TS would make a "Layer null" network), a documented divergence for hand-made input.

alluvial.save_diagram(networks, path, *, loose=False, **layout_kwargs)#

Lay out networks like layout and save the diagram as the web app saves it (“Download diagram”).

The files are “alluvial network files” (formatVersion 1): one Infomap-JSON file per network (00_<name>.json, …) with the network name, the palette (colors), each node’s colour index and module level, Infomap’s own top-level data, and an alluvial block with the options, the colour scheme with its c3 tone and offset, the module names and any custom module order. The web app opens them (drop the zip, or all files, on “Load networks”) with the same picture, and alluvial.read/layout load them back exactly. Other Infomap-JSON readers ignore the block. The text equals the web app’s for the same diagram, apart from generator.

Parameters:

  • networks (Iterable[Any]) – As for layout (names, colors, module_level, highlight, scheme, tone, offset, module_order, module_names, layout options, …). The writer reads the engine store after these steps, as the web app saves its own store.

  • **layout_kwargs – As for layout (names, colors, module_level, highlight, scheme, tone, offset, module_order, module_names, layout options, …). The writer reads the engine store after these steps, as the web app saves its own store.

  • path (str or PathLike) – Where to write. By default a zip (.zip is appended if path has another suffix). With loose=True, a directory (created if needed) for the loose files. A .json path writes the one file of a single-network diagram.

  • loose (bool, default False) – Write loose files to a directory instead of a zip.

Returns:

The path written (the zip, the directory or the .json file).

Return type:

pathlib.Path

Raises:

  • TypeError – If networks is an AlluvialGeometry (pass the networks and layout’s keywords instead).

  • ValueError – For a .json path and a diagram of more than one network.
