API reference#

The page follows the tasks of the capabilities tour: plot, lay out, read the inputs, save, and pick colors. Every entry links to the tour sections that use it, and its examples run as tests, so they match the current version. draw, plot, legend and get_artists load matplotlib on first access, so import alluvial alone does not import it.

alluvial.__version__#

The package version, a string such as "0.7.0": print(alluvial.__version__).

Plotting#

alluvial.plot(networks, ax=None, **kwargs)#

Lay out and draw in one call: draw(layout(networks, **layout_kwargs), ax, **draw_kwargs).

Parameters:

  • networks (iterable of str or PathLike, infomap.Infomap, dict or NetworkFile, or a pandas DataFrame) – Networks from left to right, as for alluvial.layout: paths, run infomap.Infomap objects, Infomap JSON dicts, NetworkFile objects, dicts mapping nodes to modules (alluvial.partition(...)), or a long-format DataFrame with one network per network value (alluvial.from_dataframe).

  • ax (matplotlib.axes.Axes, optional) – Target axes; by default a new figure sized by content (see alluvial.draw): taller with more modules, wider with more networks and longer labels.

  • **kwargs – Keyword arguments of alluvial.layout (including LayoutOptions fields) and alluvial.draw.

Returns:

get_artists(ax) returns the created artists.

Return type:

matplotlib.axes.Axes

Examples

>>> import alluvial
>>> ax = alluvial.plot([{"a": 1, "b": 1, "c": 2}, {"a": 1, "b": 2, "c": 2}], names=["2020", "2021"])

Layout and drawing keywords go together, here on an axes of your own:

>>> import matplotlib.pyplot as plt
>>> fig, ax = plt.subplots(figsize=(3.4, 2.4), layout="constrained")
>>> ax = alluvial.plot(
...     [{"a": 1, "b": 1, "c": 2}, {"a": 1, "b": 2, "c": 2}], ax=ax, colors="similarity", palette="tab10"
... )

alluvial.draw(geometry, ax=None, *, palette=None, default_color=None, module_labels=True, network_labels=True, fontsize=None, network_fontsize=None, max_label_lines=None, max_label_width='auto', avoid_label_overlap=True, label_pad=3.0, streamline_alpha=0.8, gradient=True, edgecolor='face', linewidth=0.3, rasterized=False, hierarchy=True, legend=False, label_colors='auto', module_kw=None, streamline_kw=None, hierarchy_kw=None, text_kw=None, label_kw=None, network_label_kw=None)#

Draw a laid-out alluvial diagram on a matplotlib Axes.

The shapes are in layout px (data coordinates, y up); every text size, gap and margin is in points. At each draw the labels and the axes limits are fitted to the axes size, so the diagram fills the axes, every text stays inside it and font sizes are exact at any figure size (also under layout="constrained" and after resizing).

Parameters:

  • geometry (AlluvialGeometry) – Result of alluvial.layout.

  • ax (matplotlib.axes.Axes, optional) – Target axes, drawn on at its size. By default a new figure is created, sized by content: 1.0 + 0.28 in per module of the network with the most modules (between 2 and 6 in) tall, and 0.4 + 1.1 in per further network wide, plus the width of the labels (at most as much again).

  • palette (sequence of colors, str or Colormap, optional) – Highlight colors, or a matplotlib colormap (name). Qualitative maps are used as is, continuous maps are sampled to the needed number of colors. Defaults to geometry.palette. Indices beyond the palette cycle it, with a warning.

  • default_color (color, optional) – Color of unhighlighted modules; defaults to the web app’s gray.

  • module_labels (bool, default True) – Draw module name labels (first and last network) and network names (below each network).

  • network_labels (bool, default True) – Draw module name labels (first and last network) and network names (below each network).

  • fontsize (float or str, optional) – Module label size in points or a relative size; defaults to "small" (rcParams["font.size"] / 1.2).

  • network_fontsize (float or str, optional) – Network name size; defaults to "medium" (rcParams["font.size"]).

  • max_label_lines (int, optional) – Cap on the names (lines) per module label. By default as many as fit (the web app rule: one line per 1.8 em of module height, an odd number).

  • max_label_width (float, "auto" or None, default "auto") – Longer label lines are truncated with an ellipsis to this width in points. "auto" keeps each label column within a quarter of the axes width; None never truncates.

  • avoid_label_overlap (bool, default True) – Where labels of neighboring modules would overlap, drop lines of the smaller module, then its whole label. False reproduces the web app, which lets them overlap.

  • label_pad (float, default 3) – Gap between a module and its label, in points.

  • streamline_alpha (float, default 0.8) – Streamline opacity.

  • gradient (bool, default True) – Fill streamlines whose ends differ in color with a horizontal gradient (as the web app does; a small embedded image, clipped to the streamline). If False they use the color of their left end, all vector.

  • edgecolor (default "face", 0.3) – Module edge style. The default hairline in the face color hides the antialiasing seams between stacked groups and at streamline ends; use linewidth=0 for exact web app rectangles.

  • linewidth (default "face", 0.3) – Module edge style. The default hairline in the face color hides the antialiasing seams between stacked groups and at streamline ends; use linewidth=0 for exact web app rectangles.

  • rasterized (bool, default False) – Rasterize modules and streamlines (texts stay vector) in PDF/SVG output, for very large diagrams.

  • hierarchy (bool or {"shadow", "outline"}, default True) – How to show the parent modules of expanded sub-modules (NetworkGeometry.outlines, from layout(module_level=...) or expand=), as the web app does: "shadow" (or True) draws a gray box behind each parent, offset right and down by 5 px per level; "outline" a thin solid dark gray rounded box around it (the web app’s is dotted). False or None draws nothing. A diagram of top modules has no outlines either way.

  • legend (bool, default False) – Add a legend of the highlight labels (layout(highlight=...)) above the diagram; see alluvial.legend.

  • label_colors (bool or "auto", default "auto") – Color each module label line by its node’s highlight color, as the web app does (black when gray). "auto" does so only for a diagram with highlight labels (layout(highlight=...)), where the color tells which names belong to a group.

  • module_kw (dict, optional) – Extra Rectangle / streamline properties (e.g. {"hatch": "//", "edgecolor": "white"}, {"alpha": 0.6}). A hatch is drawn in the edge color, which is the face color by default.

  • streamline_kw (dict, optional) – Extra Rectangle / streamline properties (e.g. {"hatch": "//", "edgecolor": "white"}, {"alpha": 0.6}). A hatch is drawn in the edge color, which is the face color by default.

  • hierarchy_kw (dict, optional) – Extra properties of the hierarchy shadows or outlines (e.g. {"facecolor": "0.85"}, {"edgecolor": "k", "linewidth": 1.5}, {"linestyle": "--"}).

  • text_kw (dict, optional) – Extra Text properties for all labels (e.g. {"family": "serif"}).

  • label_kw (dict, optional) – Extra Text properties for module labels or network names only (override text_kw).

  • network_label_kw (dict, optional) – Extra Text properties for module labels or network names only (override text_kw).

Returns:

The axes drawn on, with the axis turned off. get_artists(ax) returns the created artists.

Return type:

matplotlib.axes.Axes

Examples

>>> import alluvial
>>> import matplotlib.pyplot as plt
>>> geometry = alluvial.layout([{"a": 1, "b": 1, "c": 2}, {"a": 1, "b": 2, "c": 2}], names=["2020", "2021"])
>>> fig, ax = plt.subplots(figsize=(3.4, 2.4), layout="constrained")
>>> ax = alluvial.draw(geometry, ax, fontsize=6, max_label_lines=3)
>>> fig.savefig("alluvial.pdf")

alluvial.legend(ax, *, other=None, **kwargs)#

Add a legend of the highlight labels (layout(highlight=...)) of the diagram drawn on ax.

By default the legend is a row of color swatches centered above the diagram, inside the axes. It takes more rows when it is wider than the axes, and the fit makes room for it at every draw. Passing loc or bbox_to_anchor places it like any matplotlib legend instead (no room is made). Calling it again replaces the legend.

Parameters:

  • ax (matplotlib.axes.Axes) – An axes draw or plot drew on.

  • other (str, optional) – Also add an entry in the default (gray) color with this label, e.g. "other".

  • **kwargs – Axes.legend keywords (e.g. title, fontsize, ncols, frameon).

Returns:

None (with a warning) if the geometry has no highlight labels and no other.

Return type:

matplotlib.legend.Legend or None

Examples

>>> import alluvial
>>> networks = [{"a": 1, "b": 1, "c": 2}, {"a": 1, "b": 2, "c": 2}]
>>> ax = alluvial.plot(networks, highlight={"group a": ["a"]})
>>> legend = alluvial.legend(ax, other="other", title="Nodes")
>>> [text.get_text() for text in legend.get_texts()]
['group a', 'other']

Layout and geometry#

alluvial.layout(networks, *, names=None, ids=None, identifier='id', split_layers=False, colors='module_id', color_network=None, module_level=1, expand=None, highlight=None, highlight_colors=None, scheme=None, tone=None, offset=None, restore_state=True, module_order=None, module_names=None, show_bipartite_nodes=None, **options)#

Lay out an alluvial diagram of one or more partitioned networks.

Parameters:

  • networks (iterable of str or PathLike, infomap.Infomap, dict or NetworkFile, or a pandas DataFrame) – Networks from left to right. Paths are read by suffix (.tree, .ftree, .stree, .clu, .json); an infomap.Infomap must already have run. A .zip of network files (the web app’s zip upload, or save_diagram) contributes its files in archive order. A dict is Infomap JSON when its "nodes" is a list of dicts; any other dict is a partition {node: module} without Infomap (alluvial.partition): nodes are ids or names matched across networks by key, a module is an int, a path string "1:2" or a tuple of ints, and every node gets flow 1/N. A long-format DataFrame with the columns network, node, module and optionally flow gives one network per network value (alluvial.from_dataframe, which also takes other column names). When no input carries flows (only such dicts, or partitions and frames without flows), module_size and sort_modules_by default to "nodes".

  • names (sequence of str, optional) – Network names, one per network (after splitting layers; numbers are converted with str). Defaults to the file basename, "network {i}" for objects (a partition’s name if given), and "<name> layer <k>"-style names for split layers.

  • ids (sequence of str, optional) – Network ids, one per network (after splitting layers): unique, without "--". By default the file stem, "net{i}" for objects or the NetworkFile id, with colliding ids made unique as out, out_2, … An input that is split gets that suffix before splitting (out_2_layer1, …).

  • identifier ({"id", "name"}, default "id") – How nodes are matched across networks: stateId ?? id, or the node name. Applies to paths, dicts and Infomap objects; a NetworkFile keeps the identifiers it was read with.

  • split_layers (bool or sequence of bool, default False) – Split multilayer networks into one network per layer (alluvial.read(..., split_layers=True)); a sequence gives one flag per input. Split layers match their nodes by physical id.

  • colors ({"similarity", "module_id", "nodes", "layer", "physical_id", "hierarchy"} or None, default "module_id") – Coloring operation applied after the build, as in the web app: by module id (the same id gets the same color in every network), matching modules across networks, every node by its module in one network (color_network), by layer id (multilayer networks), by physical node id (state or multilayer networks), or by the module hierarchy (c3’s hierarchy(): sub-modules get colors close to their parent’s, and the same module path gets the same color in every network; use it with module_level/expand, and scheme, tone and offset set the top-module colors). None keeps the input colors (gray unless the input carries colors). Not allowed with highlight. The default is None when the input carries colors: Infomap JSON with a top-level colors (as written by save_diagram).

  • color_network (int or str, optional) – With colors="nodes", the network whose modules color the nodes (in every network), as the web app’s selected network: an index, a network id, or a name given with names= when exactly one network has it. Default the first network. Only allowed with colors="nodes".

  • module_level (int or sequence of int, default 1) – Show sub-modules down to this level (one value, or one per network): every visible module whose sub-modules go that deep is expanded, as when clicking modules in the web app. 1 shows the top modules. With colors="similarity" a sub-module that is not paired with a module of a neighboring network can stay gray, as in the web app.

  • expand (iterable of (network, module_id), optional) – Modules to expand first, in order. network is an index or a network id, module_id a path string like "1" or "1:2" (looked up when its turn comes, so [(0, "1"), (0, "1:2")] works).

  • highlight (mapping or callable, optional) – Highlight groups of nodes, each in its own color (the rest stays gray). Either {label: identifiers} (matched against node identifiers, ints allowed; an identifier may belong to one label only), or a callable (NodeInfo) -> label or None evaluated once per node. Labels are kept in mapping order (or first-appearance order) in AlluvialGeometry.highlight_labels, for draw(..., legend=True).

  • highlight_colors (sequence or mapping, optional) – Colors of the highlight labels (a list aligned with the labels, or {label: color}): color strings (any matplotlib color name, "#rrggbb" or "rgb(r, g, b)") or RGB tuples in [0, 1]. Defaults to the scheme.

  • scheme (str or sequence of colors, optional) – The color scheme of the coloring operations: a web-app scheme name (alluvial.SCHEMES lists them, e.g. "Paired", "Tableau20", "C3 Oklch"; default "C3 Sinebow") or a list of colors. Also the default highlight_colors. The C3 schemes ("C3 Oklch", "C3 Turbo", "C3 Rainbow", "C3 Sinebow", "C3 Viridis") are computed with c3 (https://mapequation.github.io/c3).

  • tone (str, optional) – The c3 tone: "vivid", "bright", "strong", "deep", "dark", "soft", "pastel" or "muted", the lightness and chroma of the C3 schemes and of colors="hierarchy" with a C3 or an interpolated (diverging, sequential or cyclical) scheme. Other schemes ignore it. Default "strong" (or the stored tone of a saved diagram).

  • offset (float, optional) – Where c3 puts the first color, in degrees around the hue source: its hue on the OKLCH hue circle ("C3 Oklch"), else 360 is the whole scheme. Applies where tone does. Default c3’s (245 for "C3 Oklch", else 0), or the stored offset of a saved diagram when its scheme is used.

  • restore_state (bool, default True) – Restore what a saved diagram (save_diagram or the web app’s “Download diagram”) stores besides the networks, colors and expanded modules: the options, the color scheme with its tone and offset, the custom module orders and the module names, as the web app opens it. Explicit keywords win: a layout option, scheme, tone or offset given here replaces the stored one (another scheme drops the stored offset), and module_order/module_names replace the stored orders/names. Files from different saves, or not all files of one save, restore their module orders and names but not the options (warned). False loads the files as plain Infomap JSON (with their colors and expanded modules).

  • module_order (mapping, optional) – {network: [module_id, ...]}: put these visible modules of a network (index, id, or a name given with names= as a string when exactly one network has it) at these positions, listed bottom to top. The unlisted visible modules keep their relative order above them; an ... (Ellipsis) in the list stands for them, so ["3", ...] puts module 3 at the bottom, [..., "3"] at the top and ["2", ..., "5"] both. Applied after the coloring as one reorder of the web app’s store (one layout however many modules move; “move up/down” in the web app gives the same order), so sort_modules_by sets the start. Module ids are those shown after expand/module_level (e.g. "1:2"); hidden modules cannot be placed.

  • module_names (mapping or callable, optional) – Custom module names, shown instead of the node names (as the web app’s module name field): either {(network, module_id): name} (network as for module_order) or a callable (ModuleInfo) -> str or None called for every module (also hidden ones) after all other steps. Names are kept in ModuleGeometry.name (save_diagram stores them); the labels are drawn on the first and last network only, as in the web app.

  • show_bipartite_nodes (bool, optional) – False hides the second node type of bipartite networks (node id >= the network’s bipartiteStartId), as the web app’s “Show bipartite nodes” switch. Default True (or the stored value of a saved diagram).

  • **options – Fields of LayoutOptions.

Returns:

Frozen geometry in the web app’s SVG coordinates (y down).

Return type:

AlluvialGeometry

Raises:

  • ValueError – For an Infomap object that has not run, an unreadable or unsupported file, no networks, an invalid option value, a module to expand that does not exist or has no sub-modules, colors with highlight, an unknown color_network or one without colors="nodes", or a module_order/module_names entry with an unknown network or module, a module given twice, or (for module_order) a hidden module.

  • FileNotFoundError – For a path that does not exist.

  • TypeError – For an unknown keyword, a single network not wrapped in a list, or an argument of the wrong type.

Warns:

UserWarning – For state networks matched by state id next to networks matched by node id (identifier="id"), a module_level deeper than a network’s module tree, highlight identifiers that match no node, duplicate node identifiers within a network, highlight labels drawn gray or in a shared color, and a diagram where no node flow is positive.

Notes

The steps run in the web app’s store, in this order: build, expand, module_level, the coloring (colors or highlight), module_order, then module_names. Each is a sequence of the store’s own operations, so the geometry matches the web app bit for bit.

Examples

>>> import alluvial
>>> geometry = alluvial.layout([{"a": 1, "b": 1, "c": 2}, {"a": 1, "b": 2, "c": 2}], names=["2020", "2021"])
>>> [network.name for network in geometry.networks]
['2020', '2021']
>>> [len(network.modules) for network in geometry.networks], len(geometry.streamlines)
([2, 2], 3)

class alluvial.LayoutOptions(height=600.0, module_width=80.0, streamline_fraction=2.0, streamline_threshold=1.0, flow_threshold=0.005, margin_exponent=4.0, zero_margins=False, vertical_align='bottom', module_size='flow', sort_modules_by='flow')#

Layout options with the web app’s defaults. Validated on construction.

Parameters:

  • height (float, default 600) – Diagram height in layout px. Must be > 0.

  • module_width (float, default 80) – Width of each network’s module column. Must be > 0.

  • streamline_fraction (float, default 2) – Gap between networks as a multiple of module_width. Must be >= 0.

  • streamline_threshold (float, default 1) – Streamlines with mean height <= this (px, not scaled with height) are not drawn. Must be >= 0.

  • flow_threshold (float, default 0.005) – Fraction of each network’s flow to hide, smallest modules first. Must be in [0, 1).

  • margin_exponent (float, default 4) – Module margins are 2 ** (margin_exponent - 2 * difference_index).

  • zero_margins (bool, default False) – Put no margin between modules.

  • vertical_align ({"bottom", "justify"}, default "bottom") – "justify" stretches the margins so every network spans the full height. "top" is rejected (the web app never implemented it).

  • module_size ({"flow", "nodes"}, default "flow") – Module height measure.

  • sort_modules_by ({"flow", "nodes", "node_id", "highlight_index"}, default "flow") – Module order key (descending). "node_id" is the mean node id.

Raises:

  • TypeError – If a value has the wrong type.

  • ValueError – If a value is out of range or not one of the allowed choices.

Examples

Pass the fields as keywords to layout or plot; the geometry keeps the options it ran with:

>>> import alluvial

>>> geometry.options.height, geometry.options.module_width
(300.0, 40.0)
>>> alluvial.LayoutOptions(vertical_align="justify").to_ts()["verticalAlign"]
'justify'

alluvial.partition(modules, flows=None, *, name=None)#

One network from a mapping of node ids or names to modules, without Infomap.

Parameters:

  • modules (mapping) – {node: module}. A node is an id (int) or a name (str); nodes are matched across networks by this key (whatever layout(identifier=...) says). A module is a positive int (a top module), a tree path string "1:2" (sub-module 2 of module 1) or a tuple or list of positive ints (1, 2); module ids start at 1, as in Infomap. The mapping order is the node order.

  • flows (mapping, optional) – {node: flow} with one non-negative finite number per node of modules. The flows are normalized to sum to 1, as Infomap’s flows do. Without flows every node gets flow 1/N, N being the number of nodes.

  • name (str, optional) – Network name (and id, unless it is empty or contains "--"). layout names an unnamed partition "network {i}", as other objects.

Returns:

Nodes in mapping order. An int node keeps its value as node id; a named node gets its 1-based position as node id and the key as name. A node’s path is its module’s path plus its position in that module, as in Infomap’s .tree files: "2:1:3" is the third node of sub-module "2:1".

Return type:

NetworkFile

Raises:

  • ValueError – For no nodes, a module value of another kind (or below 1), a key that is neither str nor int, two keys with the same string (1 and "1"), or flows that are negative, not finite, missing for a node, given for a node not in modules, or all zero.

  • TypeError – If modules or flows is not a mapping, or name is not a string.

Notes

A diagram of only flow-less networks (partition without flows, plain {node: module} dicts in layout) sizes and sorts its modules by node count: module_size and sort_modules_by default to "nodes" there, unless given.

Examples

>>> import alluvial
>>> nf = alluvial.partition({"Ann": 1, "Bo": 1, "Cy": "2:1"}, name="2020")
>>> [(n.name, n.path) for n in nf.nodes]
[('Ann', '1:1'), ('Bo', '1:2'), ('Cy', '2:1:1')]
>>> [n.flow for n in alluvial.partition({1: 1, 2: (1, 2)}).nodes]
[0.5, 0.5]
>>> [n.flow for n in alluvial.partition({"Ann": 1, "Bo": 2}, flows={"Ann": 3, "Bo": 1}).nodes]
[0.75, 0.25]

Plain dicts work directly as networks in layout and plot:

>>> geom = alluvial.layout([{"Ann": 1, "Bo": 1, "Cy": 2}, {"Ann": 1, "Bo": 2, "Cy": "2:1"}], names=["2020", "2021"])
>>> [network.name for network in geom.networks]
['2020', '2021']

alluvial.read(source: str | PathLike[str] | Any, *, name: str | None = None, identifier: Literal['id', 'name'] = 'id', states: bool | None = None, network_id: str | None = None, split_layers: Literal[False] = False) → NetworkFile#
alluvial.read(source: str | PathLike[str] | Any, *, name: str | None = None, identifier: Literal['id', 'name'] = 'id', states: bool | None = None, network_id: str | None = None, split_layers: Literal[True]) → list[NetworkFile]

Read one network into a NetworkFile (or, with split_layers=True, one per layer).

Parameters:

  • source (str, PathLike, dict, infomap.Infomap or NetworkFile) – A .tree/.ftree/.stree/.clu path (format from the suffix; Infomap’s -o states files *_states.tree/.ftree/.clu included), an Infomap -o json file (.json) or its parsed dict, an infomap.Infomap that has run, an infomap Result (from im.run(), infomap.run(...) or Network.run(); infomap >= 2.14), or a NetworkFile (returned unchanged unless split). A .zip of network files (the web app’s zip upload, or save_diagram), a directory of network files, or a list of paths gives a list, one NetworkFile per file, in archive (file-name, list) order, or in saved order when they are the files of one saved diagram.

  • name (str, optional) – Network name. Defaults to the file basename, or "network" for objects. For JSON a top-level name comes before these defaults.

  • identifier ({"id", "name"}, default "id") – Node identity across networks, as in the web app: "id" uses state_id if present else the node id, "name" the node name. See State networks below. Ignored with split_layers=True.

  • states (bool, optional) – Infomap objects only: read state nodes. None picks them for state/memory and multilayer networks (like write_tree(states=True)); False reads the physical level (write_tree(states=False)).

  • network_id (str, optional) – Network id. Defaults to the file stem for paths, or name (else "network") for objects. For JSON a top-level string id comes before these defaults.

  • split_layers (bool, default False) – Split a multilayer state network into one network per layer, like the web app’s “split layers” (alluvial.io.split_layers). Layers are ordered by layer id, named "Layer <k>" (or from a JSON layers list), get the ids "<network_id>_layer<k>" and match their nodes by physical id.

Returns:

A list (one per layer) if split_layers is true. Pass it on unpacked: layout([*read(path, split_layers=True)]).

Return type:

NetworkFile or list of NetworkFile

Raises:

  • ValueError – For an unsupported file (Infomap input .net, .csv, Newick, JSON that is not Infomap output, a saved diagram in the 2019 web-app format), a malformed file, a node whose flow is not a finite number, an Infomap object that has not been run, or split_layers=True on a network that is not a multilayer state network.

  • TypeError – For other sources, or an infomap older than 2.14.

Warns:

UserWarning – If several nodes share an identifier (the engine then matches the last one, as in the web app; checked per layer after a split), if a tree file has node names with a double quote (Infomap writes them unescaped, so the id column is misread), or if identifier="name" is combined with split_layers=True.

Notes

State networks. Networks are matched node by node through identifier, exactly as in the web app.

  • identifier="id" matches state nodes by state id. That is right for memory networks whose state ids mean the same thing in every network (you assign them in the *States section or with add_state_node). For multilayer networks Infomap assigns the state ids itself, in input order, so the same (layer, node) can get different state ids in two runs: do not match multilayer networks by "id" unless they were built from identically ordered input.

  • identifier="name" matches by physical node name: Infomap writes the physical name (or the physical id when unnamed) for every state node. A physical node with several state nodes then gives duplicate identifiers (warned; matching uses the last one).

  • The physical level (states=False or a write_tree(states=False) file) has one row per physical node and module; a node whose state nodes sit in several modules still appears more than once.

  • split_layers=True shows how one multilayer partition changes across its layers: each layer is a network, and its nodes are matched by physical node id (the identifier mode does not apply, as in the web app). A non-split network next to the layers matches them only if its identifiers are physical ids too, e.g. a first-order .tree read with identifier="id".

Examples

A parsed Infomap JSON (infomap -o json), here written inline:

>>> import alluvial
>>> nf = alluvial.read(
...     {
...         "nodes": [
...             {"id": 1, "name": "a", "path": [1, 1], "flow": 0.5},
...             {"id": 2, "name": "b", "path": [2, 1], "flow": 0.5},
...         ]
...     },
...     name="2020",
... )
>>> nf.name, nf.format, [node.name for node in nf.nodes]
('2020', 'json', ['a', 'b'])

...     nf = alluvial.read(path)
>>> nf.id, nf.name, nf.format, [node.path for node in nf.nodes]
('2021', '2021.clu', 'clu', ['1', '1'])

Split a multilayer state network into one network per layer, like the web app’s “split layers”.

Nodes are matched across the layers by physical node id (as the web app does), whatever identifiers nf was read with. Streamlines then connect the same physical node in adjacent layers.

Parameters:

  • nf (NetworkFile) – A multilayer network read at the state level (its first node has a layer_id). Not mutated: the layers get copies of the nodes.

Returns:

In layer id order: non-negative integer ids ascending, then any other ids in first-seen order (only hand-made input has those). Return type:

list of NetworkFile

Raises:

ValueError – If nf is not multilayer.

Notes

alluvial.save_diagram(networks, path, *, loose=False, **layout_kwargs)#

Lay out networks like layout and save the diagram as the web app saves it (“Download diagram”).

The files are “alluvial network files” (formatVersion 1): one Infomap-JSON file per network (00_<name>.json, …) with the network name, the palette (colors), each node’s color index and module level, Infomap’s own top-level data, and an alluvial block with the options, the color scheme with its c3 tone and offset, the module names and any custom module order. The web app opens them (drop the zip, or all files, on “Load networks”) with the same picture, and alluvial.read/layout load them back exactly. Other Infomap-JSON readers ignore the block. The text equals the web app’s for the same diagram, apart from generator.

Parameters:

  • networks (Iterable[Any]) – As for layout (names, colors, color_network, module_level, highlight, scheme, tone, offset, module_order, module_names, layout options, …). The writer reads the engine store after these steps, as the web app saves its own store.

  • **layout_kwargs – As for layout (names, colors, color_network, module_level, highlight, scheme, tone, offset, module_order, module_names, layout options, …). The writer reads the engine store after these steps, as the web app saves its own store.

  • path (str or PathLike) – Where to write. By default a zip (.zip is appended if path has another suffix). With loose=True, a directory (created if needed) for the loose files. A .json path writes the one file of a single-network diagram.

  • loose (bool, default False) – Write loose files to a directory instead of a zip.

Returns:

The path written (the zip, the directory or the .json file).

Return type:

pathlib.Path

Raises:

  • TypeError – If networks is an AlluvialGeometry (pass the networks and layout’s keywords instead).

  • ValueError – For a .json path and a diagram of more than one network.

>>> networks = [{"a": 1, "b": 1, "c": 2}, {"a": 1, "b": 2, "c": 2}]

...     [network.name for network in alluvial.read(path)]

alluvial.SCHEMES: tuple[str, ...]#

the values of scheme=.

Type:

The names of the web app’s color schemes, in the order of its scheme menu

Used in: 3.2 Color schemes · 3.3 Tones and offsets

Pass a name as scheme= to layout, plot or save_diagram, or pass a list of colors instead. The C3 schemes are computed with c3, which shows what they and its tones look like; tone= and offset= apply to them. The other schemes are those of the web app’s scheme menu. To draw with any matplotlib colormap instead, pass palette= to draw or plot.
