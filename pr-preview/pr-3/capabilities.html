alluvial capabilities: a tested tour#

This notebook walks through every public feature of alluvial, the matplotlib port of the mapequation.org alluvial web app. Each step has a short explanation, a figure where one helps, and assert checks, so the notebook doubles as an executable specification: if a cell fails, the behavior it describes has changed.

The sections:

  1. Inputs: dicts, partition and DataFrames, .tree/.ftree/.stree/.clu, Infomap JSON, infomap.Infomap objects (state, memory and multilayer networks, split_layers), the web app’s zip, NetworkFile

  2. Layout options: every LayoutOptions field

  3. Coloring: the color modes, schemes, tones and offsets, highlight groups and legends

  4. Hierarchy: module_level, expand, shadows and outlines

  5. Module names and order

  6. Drawing: axes, fonts, labels, palettes, gradients, rasterizing, restyling, saving figures

  7. Geometry access: the layout without matplotlib, to_dict

  8. Save and load: save_diagram, read, the web app

  9. Error handling: typical mistakes and their messages

  10. Performance notes

The data are the small files bundled in the repository’s tests/data plus a few seeded Infomap runs, so the whole notebook runs in well under two minutes. The shorter, story-style introduction is docs/tutorial.ipynb.

    "Two geometries are identical: every coordinate, color index, label and option, bit for bit."

def close(a, b, tol=1e-9, labels=True) -> bool:
    "Like `same`, but coordinates and flows may differ by float rounding (at most `tol`); optionally skip node labels."

    def eq(x, y):
        if isinstance(x, float) and isinstance(y, float):
            return abs(x - y) <= tol
        if isinstance(x, dict) and isinstance(y, dict):
            keys = x.keys() if labels else x.keys() - LABEL_KEYS
            return x.keys() == y.keys() and all(eq(x[k], y[k]) for k in keys)
        if isinstance(x, list) and isinstance(y, list):
            return len(x) == len(y) and all(map(eq, x, y))
        return x == y

    return eq(a.to_dict(), b.to_dict())

The public API is small. layout computes the diagram, draw renders it, and plot does both. read parses one network, partition and from_dataframe make networks from plain data, and save_diagram writes a diagram for the web app. The rest are data classes and a few small functions.

1. Inputs#

1.1 Dicts, partition() and DataFrames#

Any partition works, not only Infomap’s: one from another community detection method, from metadata, or written by hand.

  • A plain dict {node: module} is one network. A node is an id or a name, and nodes are matched across networks by this key. A module is an int (a top module), a path string "1:2" (sub-module 2 of module 1) or a tuple (1, 2). Module ids start at 1, as in Infomap.

  • alluvial.partition(modules, flows=None, name=None) makes the same network as a NetworkFile. It adds flows (normalized to sum to 1) and a name.

  • A pandas DataFrame in long format, with one row per network and node, goes straight to layout or plot. Its columns are network, node, module and, optionally, flow. alluvial.from_dataframe(df, network=..., node=..., module=..., flow=...) takes other column names and returns one partition per network.

Without flows, every node of a network gets the same flow, 1/N. When no input has flows, module_size and sort_modules_by default to "nodes", so the modules are sized and sorted by their node counts.

1.4 infomap.Infomap objects#

An Infomap object that has run can be passed directly, as can the Result that im.run() returns. Here are three snapshots of a planted-partition network: four groups of 12 nodes, where groups C and D merge in the last snapshot. All runs are seeded.

GROUPS = {"A": range(0, 12), "B": range(12, 24), "C": range(24, 36), "D": range(36, 48)}
NAMES = {u: f"{g}{u - r.start + 1}" for g, r in GROUPS.items() for u in r}


def snapshot(blocks, seed, p_in=0.5, p_out=0.01):
    "A random network with dense links inside each block of nodes."
    rng = random.Random(seed)
    block = {u: b for b, members in enumerate(blocks) for u in members}
    return [
        (u, v)
        for u in NAMES
        for v in NAMES
        if u < v and rng.random() < (p_in if block[u] == block[v] else p_out)
    ]


def run(links, **kwargs):
    im = infomap.Infomap(silent=True, seed=7, num_trials=5, **kwargs)
    im.add_nodes(NAMES.items())
    im.add_links(links)
    im.run()
    return im


A, B, C, D = (list(r) for r in GROUPS.values())
ims = [

1.5 State and memory networks#

In a state (memory) network, a physical node can have several state nodes, and the state nodes can sit in different modules: here the physical nodes p6 to p9 (later p3 to p6) take part in both groups X and Y. read takes the state level by default (states=None picks it for state and multilayer networks). Nodes are matched across networks by stateId ?? id, and colors="physical_id" colors each physical node wherever its states go.

def memory_network(shared, seed):
    "16 physical nodes in two groups, X (p0-p7) and Y (p8-p15); the `shared` ones have a state node in each group."
    rng = random.Random(seed)
    im = infomap.Infomap(silent=True, seed=7, num_trials=5)
    im.set_names({u: f"p{u}" for u in range(16)})
    groups, state = {"X": [], "Y": []}, 0
    for u in range(16):
        for side in ("X", "Y") if u in shared else ("X" if u < 8 else "Y",):
            im.add_state_node(state, u)
            groups[side].append(state)
            state += 1
    for members in groups.values():
        im.add_links((s, t) for s in members for t in members if s < t and rng.random() < 0.6)
    im.add_link(groups["X"][0], groups["Y"][0])
    im.run()
    return im

1.6 Multilayer networks and split_layers#

A multilayer network is one Infomap run over all layers. split_layers=True (in layout, or read(..., split_layers=True), which returns one NetworkFile per layer) shows each layer as its own network, as the web app’s “split layers” does. Split layers match their nodes by physical id. colors="layer" colors the unsplit network by layer.

ml = infomap.Infomap(silent=True, seed=7, num_trials=5)
ml.set_names(NAMES)
for layer, blocks in enumerate([[A, B, C, D], [A, B, C, D], [A, B, C + D]], start=1):

3. Coloring#

3.1 Color modes#

colors= runs one of the web app’s coloring operations after the build:

  • "module_id" (default): by module id, so the same id has the same color in every network,

  • "similarity": matching modules across networks share a color,

  • "nodes": every node by its module in one network, color_network (the first one by default),

  • "hierarchy": sub-modules get colors close to their parent’s (section 3.3),

  • "layer" and "physical_id": multilayer and state networks (shown in section 1),

  • None: no coloring (gray, unless the input carries colors).

3.3 Tones and offsets#

The C3 schemes ("C3 Sinebow", the default, "C3 Oklch", "C3 Turbo", "C3 Rainbow", …) are computed with c3, the color library of the web app. Two keywords change them:

  • tone= sets the lightness and chroma. The tones are "vivid", "bright", "strong" (the default), "deep", "dark", "soft", "pastel" and "muted".

  • offset= sets where the first color sits, in degrees around the hue source. On "C3 Oklch", it is the hue of the first color (default 245, a blue). On the other C3 schemes, 360 is the whole scheme (default 0).

The other schemes are fixed lists of colors and ignore both.

To get the colors themselves, use c3 (the c3-colors package) directly: c3.palette(n, tone=..., offset=...) gives the first n colors of "C3 Oklch".

def name_by_groups(module: alluvial.ModuleInfo):
    "Name a module after the groups that hold at least a quarter of its nodes."
    letters = [name[0] for name in module.node_names]

    return "+".join(major) + " team" if major else None

8. Save and load#

save_diagram(networks, path, **layout_kwargs) lays out the networks like layout and saves the diagram in the web app’s “Download diagram” format: “alluvial network files” (formatVersion 1), one Infomap-JSON file per network with the colors, expanded modules, module names, custom module orders, the layout options and the color scheme in an alluvial block. It writes a zip by default, a directory of loose files with loose=True, or one .json for a one-network diagram. read loads them back in saved order and layout restores the same diagram: the same modules, order, colors, names, options and network names. Three details differ: the coordinates agree up to float rounding (the reload sums the module flows in another order, about 1e-13 px); for the same reason, node-name labels can list nodes of exactly equal flow in another order; and the network ids are the saved file names unless ids= sets them. Saving a reloaded diagram again reproduces it bit for bit.

9. Error handling#

alluvial raises where a diagram would otherwise be silently wrong, with a message that says what to do. Each case below is a typical mistake; the check asserts the message.

    "Run fn, assert it raises `error`, and return the message."

10. Performance notes#

The engine is pure Python, so the cost grows with the number of nodes and visible modules. The four science citation networks (7170 to 7940 nodes, 350 to 470 sub-modules each at level 2) show typical times. Reading is fast; the layout dominates, and each layout call builds the diagram from scratch, so lay out once and draw the geometry as often as you like. module_order and module_level cost one layout however many modules they move or expand (earlier versions made one layout per moved module: reversing these 40 modules took 85 s).

SCIENCE = sorted(DATA.glob("science*.stree"))


def timed(label, fn):
    start = time.perf_counter()
    value = fn()
    seconds = time.perf_counter() - start
    print(f"{label:46} {seconds:5.1f} s")
    return value, seconds


science, t_read = timed("read 4 science networks", lambda: [alluvial.read(p) for p in SCIENCE])
g1, t1 = timed(
    "layout, top modules", lambda: alluvial.layout(science, names=["2001", "2003", "2005", "2007"])
)
g2, t2 = timed("layout, module_level=2", lambda: alluvial.layout(science, module_level=2))
first40 = [m.id for m in g2.networks[0].modules][:40]
g3, t3 = timed(
    "layout, module_level=2 + reverse 40 modules",
    lambda: alluvial.layout(science, module_level=2, module_order={0: first40[::-1]}),
)

print([len(n.modules) for n in g2.networks], "visible modules at level 2")
order = [m.id for m in sorted(g3.networks[0].modules, key=lambda m: -m.y)][:40]  # bottom to top
assert order == first40[::-1]
assert t3 < t2 + 10  # the 40 moves cost about one extra layout, not 40
